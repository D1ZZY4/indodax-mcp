<h1 align="center">ADR-004: MCP tool surface</h1>

- Status: historical decision carried into the TypeScript rebuild.
- Current location: packages/mcp-* and packages/indodax-mcp.

## Decision

Serve stdio and HTTP through one registry and one application composition. Keep transport concerns separate from tool definitions and application services.

The current surface is grouped around market, account, orders, portfolio, risk, paper, strategy, backtest, alerts, reconciliation, audit, system, funding, history, and operations.

## Safety consequence

Paper is the **supported mutation mode**. Live execution stays gated behind environment, credentials, acknowledgement, and risk approval, and withdrawal has **no server-side grant path**.

Tool metadata defines the expected capability, environment, authentication, destructiveness, idempotency, and audit class. That metadata is projected into standard MCP tool annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) so a client can gate a call before invoking it.

A central guard enforces authentication and environment; capability, risk, and audit enforcement stay in handlers and the risk engine. The guard checks the environment requirement before the credential requirement, so a live-only tool reports "requires live mode" instead of hiding the real blocker behind a missing-credentials message.

Annotations are advisory metadata for clients. They never replace the executable guard or risk review.

Each tool declares its input shape once. The registry and the handler consume the same schema object, because the SDK strips arguments the registered schema does not declare: a handler that parsed a wider shape would silently receive nothing for those keys.
