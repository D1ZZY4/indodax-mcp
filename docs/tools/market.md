<h1 align="center">Market tools</h1>

Public, read-only, no credentials. Every pair argument accepts any common
spelling (`btc_idr`, `BTCIDR`, `BTC/IDR`); the server normalizes it into the
exchange wire spelling per endpoint.

| Tool | Parameters | Response `data` | Notes |
| --- | --- | --- | --- |
| `indodax_server_time` | none | `{ timezone, server_time }` (ms) | Clock sync. |
| `indodax_pairs` | none | Array of `{ id, symbol, base_currency, traded_currency, ticker_id, trade_min_*, price_precision, quantity_increment, trade_fee_*, is_maintenance?, is_market_suspended?, tradable }` | `ticker_id` like `btc_idr` is the canonical input spelling. `tradable` is false for suspended or maintenance markets; skip those before spending orderbook calls on them. |
| `indodax_ticker` | `pair` string required | `{ high, low, last, buy, sell, server_time?, symbol, fetchedAt, source, ageMs, stale, rangePct, pos, spreadPct, dataQuality: { source, ageMs, cacheTtlMs, spreadFromLiveBook, note } }`, money as strings | Quotes come from a shared 30s cache. `dataQuality.spreadFromLiveBook` is true only when this call read the exchange. Measured on 2026-10-09, a cached row up to 13s old reported a spread differing from the live orderbook by as much as 0.54 percentage points, so a cached read also carries a warning and the spread must be re-read with `indodax_orderbook` before a cost-sensitive decision. `last` legitimately sits outside the quoted spread on a thin book, so that alone is not a fault signal. Depth in quote currency still needs `indodax_orderbook` or `indodax_quote`. |
| `indodax_tickers_all` | `quote`? 1-10, `limit`? 1-500 (default 100 only when neither quote nor limit is given; limit caps returned rows, total is the universe size), `fields`? array, `minVolumeIdr`?, `minRangePct`?, `maxSpreadPct`?, `minPos`?/`maxPos`? 0-1, `pairs`? names to screen without fetching the universe | `{ count, matched, total, quote, limit, fields, tickers, pairs, unknown, summary }` | Screening-ready by default: rows carry `last`, `high`, `low`, `buy`, `sell`, `vol_idr` plus derived `rangePct` (24h range pct of low), `pos` (last position in high/low), and `spreadPct` (pct of bid) whenever computable. All bounds combine with AND; a row that cannot produce a needed value fails the bound. `matched` counts rows passing filters before the limit cap, `count` counts returned rows. Unknown `pairs` names ride in `unknown` instead of failing the scan. |
| `indodax_search_symbols` | `query` required free text, optional `quote` filter, `limit` 1-200 default 25 | `{ query, matched, tradable, returned, pairs, suspended, note, summary }` | Resolve an unverified ticker against the live pair list before calling anything else. Returns `pair`, `quantityIncrement`, `tradeMinQuote`, and `suspended` per row. Unknown names come back as `matched: 0` with a note, not an error, so a screener never has to guess. |
| `indodax_orderbook` | `pair` required, `levels` int 1-100 default 20 | `{ buy, sell, bestBid, bestAsk, bestBidQty, bestAskQty, spread, spreadPct, mid, empty, note }`, money as strings | `bestBid`/`bestAsk` use the same names as `indodax_quote`, with `bids`/`asks` aliasing the `buy`/`sell` arrays. `null` on an empty side, never `0`; `empty: true` marks a one-sided book. `spreadPct` is a percentage of mid. A market without a quotable book fails with `PAIR_UNAVAILABLE` naming the pair and pointing at `indodax_search_symbols`, not a raw shape error. |
| `indodax_trades` | `pair` required, `limit` int 1-500 optional (default all) | `{ pair, count, total, limit, trades, flow: { buyCount, sellCount, buyRatio }, flowWarning?, summary }` | Each row carries `type` (exchange spelling, lowercase `buy`/`sell`) plus a `side` alias in uppercase. `flowWarning` reports `seller-dominated` below 0.2 or `buyer-dominated` above 0.8 buys on samples of 10 or more trades. |
| `indodax_candles` | `symbol` required (any spelling), `timeframe` default `"60"`, accepted `1, 3, 5, 15, 30, 60, 120, 240, 1D, 3D, 1W, 1M`, `from`/`to` unix seconds default last 24h | `{ pair, timeframe, from, to, count, bars: [{ time, open, high, low, close, volume, *Num }], note, summary }`; money fields are strings, `time` is unix seconds | Only the values above are accepted. Aliases such as `1H`, `4H` and `D` are rejected by the schema rather than costing a live call, because the exchange answers them `400 invalid TimeFrame`. Symbol is uppercased to compact form (`BTCIDR`) before the call. |
| `indodax_price_increments` | none | Raw exchange payload | Shape-level only. |
| `indodax_summaries` | none | `{ tickers: {<pair>: {...475 pairs}}, prices_24h?, prices_7d? }` | 24h/7d overview. This is the full universe, not a screener: for regime or volume filtering use `indodax_tickers_all` with bounds instead of aggregating 475 rows by hand. |
| `indodax_quote` | `pair`, `side` BUY/SELL, `quantity` positive base units, `price`? limit | `{ pair, side, quantity, requestedPrice, bestBid, bestAsk, estimatedAvgPrice, fillableQuantity, verdict, note }`, money as strings | Read-only pre-order estimate, never places anything. `verdict` is `instant` (fills around the estimate), `parked` (limit misses the book), or `partial` (depth covers only `fillableQuantity`). |
| `indodax_round_order` | `pair` required, `side`? context only, `quantity` positive base units, `price`?, `riskBudget`? positive in quote units, `stopPrice`? | `{ pair, quantity, price, adjusted, original, rules, notional, riskBudget, notionalMultiple, riskAmount, riskMultiple, riskWarning, riskNote, notes, summary, remedy }`, money as strings | Read-only preflight against the live pair list: quantity rounds down to the pair increment and price down to its precision. Reports the real numbers for a rule that blocks the order, such as an increment that leaves nothing tradable or a notional under the pair minimum. When the pair minimum alone exceeds the budget, the warning says no healthy size exists. With `stopPrice`, the stop-distance multiple warns above 1x; without it the notional multiple is sizing info only. `indodax_search_symbols` reports the same `rules` per row so an order can be sized before it is placed. Offline, the pair list is unreachable and the call explains that instead of guessing a rule. |
| `indodax_suggest_stop` | `pair`, `side` of the stop, `quantity` base units, `entryPrice`, `targetPct` percent distance, `takeProfitPrice`? for RR | `{ pair, side, quantity, entryPrice, targetPct, stopPrice, stopNotional, meetsMinimum, floors, minQuantity, maxFeasiblePct, rr, summary }` | Prices a percent-distance stop against both notional floors before committing. `maxFeasiblePct` is the widest distance that still clears the floor at this size; `rr` needs `takeProfitPrice`. |

Errors: `ValidationError` for bad pairs, `ExchangeApiError`/`ExchangeNetworkError` for upstream failures (retryable only for network/rate-limit codes).

Related: `indodax_ws_ticker` (one-shot WebSocket snapshot), `market://snapshot` and `pairs://metadata` resources.
